# ADR 003: v1.0 成品范围与验收口径

## 状态

已接受（2026-10-24）。

## 背景

当前仓库是"能跑通 MVP 的半成品"：typecheck/test/build 全绿，但生产构建白屏、队列是库的副本、进度条不可拖动、HiFi 面板展示 mock 数据、导航与多个按钮是死控件。需要把范围收口到一个可日常使用、可交付的 v1.0，而不是继续堆功能。

## 决策

### 1. 终点定义

v1.0 = 可安装的本地 HiFi 桌面播放器，具备「选目录 → 扫库 → 播放 → 队列 → 信号信息 → 重启恢复」的完整闭环，并能产出 Windows 免安装包。

### 2. 信息架构：三页

| 页面 | 职责 | 必须有 |
| --- | --- | --- |
| 音乐库 | 浏览与检索本地曲目 | 扫描状态（空/扫描中/成功/失败）、搜索、排序、刷新、播放某曲 |
| 播放队列 | 管理待播顺序 | 当前队列、跳到任意曲目、移除曲目、清空、播放模式 |
| 设置 | 偏好与边界说明 | 主题、背景壁纸、动效开关、关于与"未接入 audio-core"说明 |

导航使用左侧固定 rail；**不设置常驻右侧面板或舞台**。队列是独立页面，不是侧边舞台。

### 3. 播放语义

- 队列与库解耦：`library` 是扫描结果，`queue` 是待播序列，默认由库顺序生成，可单独编辑。
- 播放模式：`sequential`（顺序）、`repeat-one`（单曲循环）、`shuffle`（随机）。
- `sequential` 播完最后一首停止；`shuffle` 需保证一轮内不重复。
- 上一首：播放位置 > 3 秒时回到本曲开头，否则切上一首（业界一致行为）。
- 进度可拖动；拖动期间不跟随 `timeupdate` 抖动。

### 4. HiFi 信息口径（诚实三态）

| 字段 | 来源 | 展示规则 |
| --- | --- | --- |
| 格式（flac/wav/mp3/m4a/ogg） | 文件扩展名 | 直接展示 |
| 标题/艺术家/专辑 | 文件名推断 | 低于阈值时显示"未知艺术家/未知专辑" |
| 采样率 / 位深 | 当前无法读取 | 显示 `—` 并标注"需 audio-core" |
| 输出设备 / 独占模式 | 未接入 | 显示"未接入 audio-core"，不得出现 mock 设备名 |

删除 `mockHifiSignalInfo` 与任何伪造信号值。

### 5. 持久化

单目录模型。主进程把 `{ musicDirectory, backgroundImage, theme, reduceMotion, volume }` 存到 `app.getPath("userData")/settings.json`，渲染层通过 preload 读写，不直接接触文件系统。

### 6. 交付形态

- `pnpm build` 同时产出渲染层 `dist/` 与主进程 `dist-electron/`。
- `pnpm start` 启动生产构建。
- `electron-builder` 产出 Windows portable 包（`release/`，不入库）。打包失败不阻塞代码交付，但必须如实报告。

## 不做

见 [backlog](../product/backlog.md)：Rust audio-core、标签解析与封面、多目录、歌词、角色舞台/Live2D/MV、自动更新、在线流媒体。

## 影响

- 工作量集中在渲染层重构与构建链路，主进程改动小（新增设置读写、背景图白名单）。
- 需要为 store、队列、播放模式、格式化补齐单测（现有 17 个用例不足）。
- 交付节奏：S1–S8 阶段推进，每阶段结束暂停确认。
