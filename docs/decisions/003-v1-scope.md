# Arlt HiFi Player v1.0 范围与验收口径

## 状态

已接受（2026-10-24）。§2 的信息架构与 §1 的终点定义被 [ADR 005](005-scene-gallery.md) 修订：库的主视图改为 3D 展厅。

2026-10-30 起，v1.0 范围由 [ADR 007](007-v1-scope-convergence.md) 收敛为“单排货架 + CD 盒 + 唱片机”：队列页、播放台、收藏、长廊 / Bay、列表降级、三档播放模式不再作为 v1.0 验收项；本文保留作历史。

## 背景

当前仓库是"能跑通 MVP 的半成品"：typecheck/test/build 全绿，但生产构建白屏、队列是库的副本、进度条不可拖动、HiFi 面板展示 mock 数据、导航与多个按钮是死控件。需要把范围收口到一个可日常使用、可交付的 v1.0，而不是继续堆功能。

## 决策

### 1. 终点定义

v1.0 = 可安装的本地 HiFi 桌面播放器，具备「选目录 → 扫库 → 收藏 → 在 3D 展厅浏览 → 播放台播放 → 队列 → 信号信息 → 重启恢复」的完整闭环，并能产出 Windows 免安装包。

### 2. 信息架构：场景 + 系统层

| 视图 | 职责 | 必须有 |
| --- | --- | --- |
| 展厅（主视图） | 浏览与打开曲库 | CD 长廊（每 24 首一段 Bay）、生长与消退、拖拽/滚轮/双击、悬停标签、两段式跨段移动、搜索飞行 |
| 播放台 | 播放当前曲目 | 悬浮 CD、倾斜/转动、控制层、信号信息、返回 |
| 列表视图 | 检索与降级 | 扫描状态、搜索、排序、刷新、播放某曲、键盘可达 |
| 播放队列 | 管理待播顺序 | 当前队列、跳到任意曲目、移除曲目、清空、播放模式 |
| 设置 | 偏好与边界说明 | 主题、动效、场景开关、收藏管理、关于与能力边界 |

**不设置装饰性右侧舞台**；队列是独立页面，不是侧边舞台。3D 场景的合法性见 ADR 005（场景即内容即导航）。

### 3. 播放语义

- 队列与库解耦：`library` 是扫描结果，`queue` 是待播序列，默认由库顺序生成，可单独编辑。
- 播放模式：`sequential`（顺序）、`repeat-one`（单曲循环）、`shuffle`（随机）。
- `sequential` 播完最后一首停止；`shuffle` 需保证一轮内不重复。
- 上一首：播放位置 > 3 秒时回到本曲开头，否则切上一首（业界一致行为）。
- 进度可拖动；拖动期间不跟随 `timeupdate` 抖动。

### 4. HiFi 信息口径（诚实三态）

| 字段 | 来源 | 展示规则 |
| --- | --- | --- |
| 格式（flac/wav/mp3/m4a/ogg） | 文件扩展名 | 直接展示 |
| 标题/艺术家/专辑 | 标签解析，失败回退文件名 | 缺失时显示"未知艺术家/未知专辑" |
| 时长 / 采样率 / 位深 | 标签解析（`music-metadata`） | 读到就显示真实值；读不到显示 `—` |
| 输出设备 / 独占模式 | 未接入 | 显示"未接入 audio-core"，不得出现 mock 设备名 |

删除 `mockHifiSignalInfo` 与任何伪造信号值。

### 5. 元数据与封面（v1.0 增补）

经确认，把原属 backlog 的元数据解析拉进 v1.0：

- 依赖 `music-metadata`（纯 JS 读文件头，不解码音频），运行在主进程扫描器内，不跨越 preload 边界。
- 读取：标题、艺术家、专辑、时长、采样率、位深、编码、内嵌封面。
- 封面：提取后写入 `app.getPath("userData")/covers/` 缓存，按曲目 id 命名，通过受控媒体协议读取；不做封面编辑与联网抓取。
- 该变更影响 `Track` 类型、扫描器、媒体协议白名单，必须在 S3 定型类型、S5 落地，不允许事后补。

### 6. 持久化

单目录模型。主进程把 `{ musicDirectory, backgroundImage, theme, reduceMotion, volume }` 存到 `app.getPath("userData")/settings.json`，渲染层通过 preload 读写，不直接接触文件系统。

### 7. 交付形态

- `pnpm build` 同时产出渲染层 `dist/` 与主进程 `dist-electron/`。
- `pnpm start` 启动生产构建。
- `electron-builder` 产出 Windows portable 包（`release/`，不入库）。打包失败不阻塞代码交付，但必须如实报告。

## 不做

见 [backlog](../product/backlog.md)：Rust audio-core、多目录、歌词、装饰性舞台/角色立绘/Live2D/MV、自动更新、在线流媒体、场景物理模拟。

## 影响

- 工作量集中在渲染层：系统层重构 + 3D 场景（S2R 系列为最大单项）。
- 主进程改动较小：设置读写、封面缓存、图片白名单。
- 需要为 store、队列、播放模式、场景空间映射（`getGalleryAnchor` / `getBayCount`）、格式化补齐单测。
- 交付节奏：按 roadmap 顺序推进，每阶段结束暂停确认。

## 修订记录

- 2026-10-24：接收 ADR 005，库的主视图从列表改为 3D 展厅，收藏提前进 v1.0。
