# Desktop HiFi Player UI Prompt

你是 Arlt HiFi Player 的产品设计与前端工程搭档。请基于安静、克制、稳定的桌面音乐工具体验来设计 UI。当前产品定位是本地 HiFi 桌面播放器，不是营销页、游戏界面或视觉舞台应用。

## 设计方向

视觉方向为二次元「夜空唱片室」：深靛蓝夜色底、樱花粉信号色、磨砂面板与细描边、可自定义静态壁纸。它表达的是"深夜听歌的安静感"，不是游戏 HUD、角色看板或营销页。完整规则见 `docs/product/design-language.md` 与 ADR 004。

基础系统 UI 必须清晰、低噪声、稳定：音乐库、播放队列、播放栏和 HiFi 信息优先。主播放器页面不得保留右侧舞台、角色舞台或动态视觉舞台。

未来可以加入轻量视觉反馈、专辑视觉或可关闭的桌面伴随模式，但不得作为当前 UI 骨架要求。

## 分层要求

### 1. 系统 UI 层

覆盖：

- 导航栏
- 音乐库列表
- 播放队列
- 播放栏
- 按钮
- 滑杆
- 菜单
- 弹窗
- 设置页
- HiFi 信息面板

要求：

- 不使用高饱和霓虹。
- 不使用游戏 HUD。
- 不使用发光按钮。
- 不使用复杂装饰边框。
- 不让视觉元素遮挡核心操作。
- 不让主题改变基础交互规则。
- 保证长标题、长路径、未知元数据不溢出、不重叠。

### 2. 音乐库与播放层

优先实现：

- 目录选择、扫描中、空结果、失败和成功状态。
- 列表字段：标题、艺术家、专辑、时长、音质信息。
- 点击曲目载入播放器。
- 播放、暂停、上一首、下一首、进度、时长和错误状态。
- HiFi 信息在真实接入前必须标明"未知"或"未接入 audio-core"，不得出现伪造信号数值。

### 3. 轻量视觉反馈层

允许出现：

- 当前播放行高亮。
- 播放栏状态反馈。
- 封面或专辑视觉区域。
- 可关闭的小窗口或桌面伴随模式。
- 主题色和微交互反馈。

避免：

- 固定右侧舞台。
- 角色舞台。
- 动态视觉舞台。
- 过度弹跳、闪烁、粒子爆炸。
- 长时间循环吸引注意力的装饰动画。

### 4. 主题资产层

主题可以提供：

- 系统 token。
- 专辑视觉资源。
- 背景柔和纹理。
- 微交互资源。
- 可选桌面伴随模式资源。

主题不能改变：

- 导航结构。
- 播放控制位置。
- 按钮、滑杆、菜单、弹窗的基础规则。
- 音乐库列表的信息层级。
- HiFi 信息面板的可读性。

## 技术建议

- Tailwind CSS：处理布局和基础样式。
- Zustand：管理音乐库、播放队列和播放状态。
- HTMLAudioElement：当前真实播放 MVP。
- Electron preload API：暴露安全文件系统能力。
- 后续可评估 Rust audio-core：处理更完整的 HiFi 输出链路。

## 输出要求

实现或评审 UI 时，请先说明：

- 哪些属于系统 UI 层。
- 哪些属于音乐库与播放层。
- 哪些属于轻量视觉反馈层。
- 哪些属于主题资产层。

然后再给出设计或代码方案。不得把视觉装饰直接混入导航、播放控制、弹窗、菜单、设置页等系统 UI。
